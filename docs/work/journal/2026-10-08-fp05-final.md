## Воспроизводимый порядок

1. Для автономной регрессии запустить `npm test`, `npm run lint`, `npm run typecheck`. Live-gated skips не считать live pass. Browser harness и его точная команда перечислены в evidence index.
2. Для CMS использовать development targets из [inventory](../../setup/development-services.md), один общий seed namespace и последовательные операции. Сначала dry-run seed и проверка owned set; затем guest draft denial/authenticated preview, publish/update/unpublish/rename, HTML и metadata. Проверять автоматическую webhook delivery отдельно от ручной очистки cache.
3. Собирать метрики командой `npm run collect -- --env development --apply` только с development writer. Сверять source identity, даты/last-valid и HTML. Для отказов использовать isolated PostgreSQL rehearsal из исходного evidence index; не останавливать общий live collector ради crash-теста.
4. Для AI-review публиковать только собственный synthetic review через Studio, наблюдать score после automatic webhook и восстанавливать/удалять owned fixture с проверкой полной принадлежности. Не выдавать synthetic review за редакционную оценку CMS.
5. CRM smoke проводить только с выделенным dev alias владельца из secret store: comparison → форма, lost reply → retry → duplicate, SQL hash-only readback, точная cleanup. Alias, request credential, raw payload и anonymous IDs в artifacts не сохранять. Grant/PostHog smoke выполняется отдельно от no-consent; synthetic analytics events направляются только в dev project.

Для нового live replay сначала требуется постоянный development webhook target либо отдельно разрешённая временная настройка доступа: прежний bypass отозван, test webhook выключен. Историческое успешное evidence не доказывает действующую непрерывную delivery после cleanup. Нынешний проход не восстанавливает временный доступ автоматически.

В текущем проходе исправлен один конкретный дефект offline-пути: `fixtureModel()` возвращал пустой `comparisons` при наличии опубликованной synthetic пары в domain fixtures. Теперь web projection содержит эту пару, canonical fixture route и comparison CTA доступны; live GROQ/client/cache/auth не менялись. Отдельный Playwright config и временный launcher не копируют `.env`, не наследуют live credentials и не переиспользуют чужой dev server. Неизвестное/отклонённое согласие, реальный in-memory accepted/neutral duplicate и intercepted unavailable/lost-response retry проверяются браузером. Механизмы actual CRM/DB failure и granted SDK lifecycle остаются в отдельных service/live evidence.

Проверки финального source: 295 tests passed, 13 live-gated skipped; lint/typecheck/diff whitespace passed. Независимые профильные проверки: CMS/metrics 80 offline tests, lead/measurement 77 offline tests, fixture projection follow-up 31 tests. Это пересекающиеся наборы; их суммы не выдаются за количество уникальных тестов. Дополнительный PostgreSQL replay — 8 tests, включая два настоящих SQL-теста. Next/Studio build наследуется из предыдущего прохода; новая production сборка в этом проходе не заявляется.

Первые попытки выявили неверный fixture slug, неоднозначный test selector и оставшиеся временные копии при принудительном SIGKILL; они исправлены, история попыток отражена в очищенной browser summary.
