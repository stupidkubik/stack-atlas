# 0002. Рамка CMS и решения до начала кода

> Историческая запись: частично заменена [ADR 0013](0013-marketing-v1-and-simple-pipeline.md). Пункты 10–13 о подтверждённой подписке/очереди относятся только к будущему newsletter. В v1 действует accepted CRM-заявка, consent и ограниченный retry по 09/10. Автоматические детекторы AI не обязательны. При конфликте применять актуальные спецификации 02–12.

Дата: 5 октября 2026. Статус: принято в текущем разборе по поручению владельца; детали неполных сигналов и выбор провайдеров отложены до спецификаций.

## Контекст и варианты

Владелец выбрал рамку CMS, обязательную AI-readiness, разделение встроенных/внешних типов и npm-имени/URL. Остальные вопросы поручено проверить и оформить как решения при отсутствии очевидных проблем. Сохраняется [английский язык v1 и фокус на ядре](0001-core-and-english-v1.md).

Альтернативы: широкий каталог JS/TS; все шесть AI-сигналов сразу; переменный знаменатель при сбоях; автоматическое признание официальности по имени; прямой доступ агента к CMS. Выбран узкий каталог CMS, три версионируемых сигнала и проверяемая принадлежность; изменения контента контролирует сервер.

## Принятые решения

| № | Вопрос | Решение | Когда применяется |
| --- | --- | --- | --- |
| 1 | Тематика | Каталог headless CMS для JS/TS-сайтов. Карточка представляет CMS-продукт; npm-пакеты/SDK и репозитории — связанные сущности. Формы, i18n и валидация не входят в стартовый набор | v1 |
| 2 | AI-readiness | Обязательная особенность ядра: снимок сигналов, доказательства, даты, методология, версия формулы и ручное подтверждение | v1 |
| 3 | Неполные сигналы | Подробные состояния, свежесть, исключения и переходы описываем в `07-ai-readiness.md`. До этого ошибки не превращаем в отсутствие, числовой итог для неполного набора не публикуем | До реализации детекторов |
| 4 | Формула | Три сигнала с постоянными весами 25/20/20, знаменатель 65; правила и примеры ниже. Новые сигналы требуют новой версии | v1 |
| 5 | TypeScript | Различаем встроенные типы, внешние `@types`, отсутствие и незавершённую проверку. Типы относятся к выбранному основному JS/TS SDK или пакету CMS, а не ко всему продукту | v1 |
| 6 | MCP/skills | MCP в v1; skills позже. Поиск даёт кандидатов; подтверждение требует доказательства связи с владельцем и ручной проверки. Community-инструменты отображаются отдельно и не дают баллы официального сигнала | v1; skills — расширение |
| 7 | URL | Стабильный ID продукта, `packageName` и безопасный `routeSlug` — разные поля. Slug продукта задаёт редактор, например `example-cms`; scoped-имя хранится без преобразования. Переименование пакета не меняет URL; изменение slug создаёт постоянный редирект | v1 |
| 8 | Сравнения | Канонический ключ — отсортированная пара стабильных ID. A/B и B/A — одно сравнение; обратный URL получает 308 на канонический. Порядок колонок хранится отдельно. Индексация требует опубликованного содержательного вывода | v1 |
| 9 | Масштаб сравнений | Не создаём все пары автоматически. Для n CMS потенциальных пар n(n−1)/2; для нескольких групп считаем уникальные пары, устраняя пересечения. Стартовый набор — выбранные редакционные сравнения | v1 |
| 10 | Конверсия | Разделяем принятую заявку и подтверждённый адрес. Основная конверсия подписки — переход к подтверждённому адресу; email в аналитические свойства не передаём | Маркетинговая итерация |
| 11 | Дедупликация | Отдельно контролируем операцию заявки, контакт, webhook, письмо и аналитическое событие. Повторная доставка допустима; обработка идемпотентна. Upsert контакта не заменяет остальные проверки | Маркетинговая итерация |
| 12 | Отказы | Состояние операции и задания доставки хранится долговременно. Сервер приложения владеет переходами, повторами и журналом; есть ограничение попыток и ручное восстановление. Хранилище, таймауты и сроки хранения выбираем в архитектуре/спецификации подписки | До маркетинговой реализации |
| 13 | Consent/A/B | До согласия не запускаем необязательную аналитику, не сохраняем UTM/вариант и показываем базовый hero. После согласия назначаем устойчивый вариант и фиксируем exposure после показа. Отказ прекращает сбор и удаляет соответствующее локальное состояние. Основная конверсия эксперимента учитывается только при допустимом связывании с exposure | Маркетинговая итерация |
| 14 | Индексация | Поиск/фильтры и неготовые публичные сравнения: `noindex`, вне sitemap, доступны обходу для чтения директивы. Индексируются готовые канонические страницы. Preview защищён доступом, `noindex` — дополнительная мера | v1 |
| 15 | Права Sanity | Не рассчитываем на бесплатные custom roles. Агент не получает токен записи: вызывает серверный обработчик с allowlist полей, проверкой одобрения и revision. Редакционные изменения — только в черновик; публикация человеком. Импорт имеет отдельный контролируемый путь записи снимков | Импорт в v1; агент позже |
| 16 | Кеш/вариант | Общая кешируемая страница не содержит персонального варианта. При расширении hero меняется в отдельном клиентском компоненте после согласия; базовый hero виден до назначения. SSR-персонализация потребовала бы отдельного решения о кеше | Маркетинговая итерация |
| 17 | SEO-валидация | Проверяем синтаксис JSON-LD, соответствие видимому контенту и условия конкретного типа. Rich Results Test — проверка пригодности, не обещание выдачи. Не придумываем рейтинги/отзывы ради разметки | v1 |

## Формула AI-readiness v1

Версия: `cms-ai-support-v1`. Это редакционный индекс наличия средств поддержки, а не измеренная эффективность агентов. Веса — выбор проекта, не результат исследования. Сохраняем относительные веса трёх сигналов из концепции.

| Сигнал | Вес | Значение при завершённой проверке |
| --- | --- | --- |
| Типы основного JS/TS-пакета | 25 | 1 — встроенные; 0.5 — только внешние `@types`; 0 — подтверждённое отсутствие |
| Официальный llms.txt | 20 | 1 — найден и проверен на официальном ресурсе; 0 — подтверждённое отсутствие в заданной области проверки |
| Официальный MCP | 20 | 1 — подтверждён; 0 — в заданной области проверки подтверждённого официального MCP нет |

`score = round(100 × (25 × types + 20 × llms + 20 × mcp) / 65)`

Примеры при полностью завершённых проверках: все три сигнала — 100; встроенные типы и llms.txt без MCP — 69; внешние типы и оба остальных сигнала — 81. Сырые компоненты сохраняются вместе с округлённым итогом.

При неполной проверке показываем сигналы и отсутствие итогового балла. Знаменатель не уменьшаем из-за сбоя. Последний завершённый снимок можно показывать отдельно с его датой; результаты разных запусков не смешиваем незаметно. Детали этого поведения, определения отсутствия и полноты остаются задачей полной документации, как поручил владелец.

CMS без сопоставимого JS/TS-пакета можно описать в каталоге, но до определения применимости типов ей не присваивается этот итоговый балл. Загрузки SDK подписываются как загрузки SDK и не выдаются за число пользователей CMS. Сравнение оценок возможно только в одной версии методологии.

## Подтверждение MCP и skills

Первый источник — официальная документация CMS или репозиторий, на который она ссылается. Реестр MCP помогает обнаружить сервер и проверить namespace издателя. Подтверждённый namespace стороннего автора не означает связь с владельцем CMS.

Для положительного официального сигнала сохраняем ссылку с официального ресурса на конкретный MCP/skills, идентичность владельца, URL инструмента, дату и запись ручного подтверждения. Расположение в известном каталоге и совпадение названия сами по себе недостаточны. Официальный MCP может быть подтверждён и без записи в реестре.

В v1 коллектор проверяет заранее отобранные официальные источники и предлагает кандидатов; редактор подтверждает принадлежность. Произвольный MCP не запускаем ради обнаружения. Для skills в будущем применяем те же правила: папка `SKILL.md` не доказывает ни официальность, ни назначение для пользователей CMS. Новый сигнал не меняет старые оценки задним числом.

## Результат проверки утверждений

Проверены документы первичных источников 5 октября 2026; интеграционные запросы к выбранным аккаунтам ещё не выполнялись. Источники подтверждают возможности и ограничения, а проектные правила выше — наши решения на их основе.

- TypeScript различает bundled declarations и внешние `@types`; само отсутствие поля `types` не доказывает отсутствия деклараций. Проверка учитывает разрешение entry points и `exports`, а детали фиксируются в контракте детектора. [Publishing](https://www.typescriptlang.org/docs/handbook/declaration-files/publishing.html), [Modules reference](https://www.typescriptlang.org/docs/handbook/modules/reference).
- npm scoped-имя имеет отдельную область scope и имя пакета: его нельзя безусловно использовать как один сегмент пути. [npm scope](https://docs.npmjs.com/cli/v11/using-npm/scope/).
- MCP Registry аутентифицирует издателя в namespace; связь этого издателя с конкретной CMS требует нашей проверки. [Registry authentication](https://github.com/modelcontextprotocol/registry/blob/main/docs/modelcontextprotocol-io/authentication.mdx).
- В актуальном предложении llms.txt допустим также путь вроде `/docs/llms.txt`; обязательным элементом формата является H1. Требование ссылок для полезности можно ввести отдельно, но это не обязательность по формату. Детектор нельзя ограничивать только корнем сайта. [llms.txt v2](https://llmstxt.org/).
- Brevo документирует отдельный double-opt-in flow и повторные отправки webhook. Это подтверждает необходимость разделять состояния и учитывать повторную доставку; выбор Brevo этим не утверждается. [DOI API](https://developers.brevo.com/reference/create-doi-contact), [Retry mechanism](https://developers.brevo.com/docs/retry-mechanism).
- PostHog предоставляет управление сбором и приватностью; режим согласия — выбранный контракт продукта, а не автоматическая гарантия соответствия законодательству. [Privacy controls](https://posthog.com/docs/privacy).
- Блокировка обхода препятствует чтению `noindex`. [Google: block indexing](https://developers.google.com/search/docs/crawling-indexing/block-indexing).
- Document-level custom access control Sanity требует соответствующего Enterprise-плана. Скрытое поле Studio не является границей доступа. `ifRevisionId` предотвращает изменение уже изменённой версии, но не заменяет авторизацию. [Access control](https://www.sanity.io/docs/developer-guides/restrict-access-to-specific-documents), [Conditional patches](https://www.sanity.io/docs/apis-and-sdks/js-client-mutations).
- Стратегия персонализации должна учитывать режим кеша выбранной версии Next.js. Клиентское назначение hero — наш способ сохранить общий публичный HTML; конкретные API проверяем при выборе версии. [Next.js caching](https://nextjs.org/docs/app/guides/caching).
- Валидная структурированная разметка не гарантирует расширенный результат поиска. [Google structured data policies](https://developers.google.com/search/docs/appearance/structured-data/sd-policies).
- Число пар — комбинаторный расчёт, не свойство API: для 80 инструментов в 10 непересекающихся равных группах `10 × 8 × 7 / 2 = 280`. Для одной группы из 8 CMS — 28; публикуем лишь выбранные пары.

## Последствия и проверка

Обновляем [продуктовую рамку](../02-product-and-scope.md) и [разбор](../01-project-breakdown.md). До кода детекторов готовим полную методологию, включая неполные сигналы. До маркетинговых интеграций выбираем хранилище операций и проверяем конкретный CRM/почтовый цикл.

Приёмка должна воспроизводить формулу на примерах, проверять коллизии пары/slug, сохранность редакционного текста и отказ источника. Для расширений отдельно проверяем повтор webhook, отсутствие событий без согласия, изоляцию кеша и отклонение неразрешённой правки агента. Принятое решение не отмечается как реализованная проверка.
