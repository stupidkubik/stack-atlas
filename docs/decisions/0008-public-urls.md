# 0008. Языковой префикс и публичные URL — S5, вариант A

> Частично заменена [ADR 0014](0014-learning-project-simplifications.md): карточка продукта — `/en/tools/{routeSlug}/` вместо `/en/libraries/{routeSlug}/`. Остальные правила действуют.

Дата: 5 октября 2026. Статус: принято владельцем проекта.

## Контекст и варианты

Рассмотрены A — префикс у всех языков, B — английский без префикса, C — добавление префикса с миграцией позже. Владелец принял рекомендацию A и предложенный комплект правил.

## Решение

- Единственная активная локаль v1 — `en`; английские страницы используют `/en/`.
- Главная `/en/`; категория `/en/categories/{categorySlug}/`; стартовый каталог `/en/categories/cms/`.
- Карточка `/en/libraries/{routeSlug}/`; сравнение `/en/compare/{firstSlug}-vs-{secondSlug}/`.
- Методология `/en/methodology/ai-readiness/`.
- Дополнение ADR 0013: `/en/request-shortlist/` и `/en/privacy/`; HTTP/index policy — актуальный 08.
- Поиск и фильтры — query на маршрутах каталога по существующему контракту сценариев/SEO.
- Публичные HTML-маршруты заканчиваются `/`; технические ресурсы `/robots.txt` и `/sitemap.xml` — без завершающего `/`.
- `/` постоянно перенаправляется 308 на `/en/`. Автоопределение языка не вводим.
- Новые языки получают собственный префикс после готовности переводов; английские URL сохраняются. Переключатель языков в v1 отсутствует.

Принятые ранее правила независимого slug, канонической пары и редиректов сохраняются. В slug продукта резервируется разделитель `-vs-`. Неактивная локаль и отсутствующий опубликованный перевод возвращают 404; английский fallback под чужой локалью не выдаётся.

## Последствия и проверка

Единый URL builder используется ссылками, canonical, sitemap и redirects. Конкретный production origin выбирается до релиза. Проверяем корневой redirect, нормализацию slash, обратную пару, rename, отсутствующую локаль и query-состояния по [SEO-контракту](../08-localization-and-seo.md). Принятие URL не подтверждает их реализацию.
