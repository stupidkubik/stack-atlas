# 0014. Упрощения учебного v1 перед стартом кода

Дата: 5 октября 2026. Статус: принято владельцем проекта.

## Контекст

PkgCompass — учебный портфолио-проект, а не продукт с пользователями и обязательствами. Ревью документации перед FP-01 нашло механизмы, у которых нет видимого потребителя: копия AI-review в БД, история снимков, которую никто не показывает, дубль email в PostgreSQL с зашифрованными бэкапами. Нашлись и пробелы: cron GitHub отключается в неактивном репозитории, форма не работает на preview-деплоях, у дизайна нет задачи. Владелец принял все рекомендации ревью.

Принцип: оставляем механизм, если он показывает навык из цели проекта или защищает от реальной ошибки. Гарантии уровня продакшен-сервиса без пользователей не добавляем.

## Решение

1. **AI-review читается из Sanity.** Публичный read layer берёт опубликованный `aiReview` и считает балл доменной функцией. Если `mappingKey` review не совпадает с текущим mapping, сигналы показываются как `unknown` с причиной `mapping_changed`, `score = null`. Таблицы `ai_snapshots`, режима `collect --mode ai`, состояния «Review update pending» и отдельного «предыдущего полного балла» нет. Незавершённый review остаётся черновиком в Studio, а посетитель видит прежнюю опубликованную версию.
2. **Метрики хранят только текущее состояние.** Одна строка на продукт, источник и метрику: последняя попытка и последнее валидное значение с датой и периодом. Истории снимков, retention и cleanup нет. Ряд загрузок npm по дням за 30 дней collector получает одним запросом к range API и хранит в текущей строке: спарклайн есть с первого дня без собственной истории.
3. **Email не хранится в PostgreSQL.** Brevo — единственное место с адресом. В БД остаются `requestId`, HMAC-ключ дедупликации, HMAC payload, сценарий, состояние, `conversionId` и даты. Lease, лимит попыток, операторский `leads:retry` и зашифрованный бэкап заявок не нужны. Повтор и конкурентные запросы безопасны за счёт идемпотентного upsert в Brevo и условного перехода в `accepted`. Срок хранения 30 дней применяется к строкам БД и к контактам в проектном списке Brevo по атрибуту даты заявки.
4. **Свежесть AI-evidence — 90 дней** от `evidenceAsOf`. Старше — пометка «Checked over 90 days ago». Studio подсвечивает review старше 75 дней.
5. **Ежедневный запуск через Vercel Cron.** Workflows в GitHub Actions не используют `schedule`: GitHub отключает его через 60 дней без активности в публичном репозитории. Раз в день Vercel Cron вызывает защищённый endpoint, а тот через GitHub API запускает `workflow_dispatch` для сбора метрик и maintenance. Collector остаётся CLI в Actions.
6. **Карточка продукта — `/en/tools/{routeSlug}/`, сущность — `product`.** Связанные имена: `productContent`, `productId`, `product_id`, `routeType = product`. Название PkgCompass не меняется.
7. **Origin формы зависит от окружения.** Production принимает только origin `SITE_URL`. Development дополнительно принимает origin текущего preview-деплоя из системных переменных Vercel `VERCEL_URL` и `VERCEL_BRANCH_URL`.
8. **Дизайн — отдельная задача CW-16** до CW-08: токены, типографика, сетка, ключевые экраны desktop/mobile. Оценка 8–12 часов, она закрывает отложенную работу из ADR 0011.

Дополнительно:

- Форма и privacy-страница прямо говорят, что помощь бесплатная и некоммерческая. Это согласуется с Vercel Hobby.
- У сравнения есть необязательное поле `disclosure`. Для пар с Sanity оно обязательно по редакционному чек-листу: сайт сам построен на Sanity.
- Обязательные evidence-файлы в run нужны только для проверок с `--gate Qxx`. Для остальных задач достаточно записей `check`. ID задач и доска не меняются, добавлена только CW-16.

## Что заменяется

Этот ADR имеет приоритет над соответствующими пунктами ADR 0013. Конкретно заменены: история снимков за 30 дней и последний полный AI-снимок, перенос AI-review в БД, хранение email и бэкап private lead state, пути `/en/libraries/` из ADR 0008, имя сущности `library` из ADR 0009. Остальное в ADR 0013 действует.

## Последствия

- Исчезают AI-run, история метрик и бэкап заявок. Шаги restore сводятся к трём: импорт CMS export, миграции с нуля, новый сбор метрик.
- Потеря таблицы заявок допустима: в Brevo контакты сохранятся, в худшем случае повторная заявка в течение 30 дней даст лишнюю конверсию.
- После ротации `LEAD_HMAC_SECRET` старые ключи дедупликации перестают совпадать. Последствие то же и такое же допустимое.
- Оценка остаётся 66–106 часов: упрощения компенсируют добавленный дизайн.
