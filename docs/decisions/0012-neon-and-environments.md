# 0012. Neon и переход окружений A → B — S9

> Историческая запись: частично заменена [ADR 0013](0013-marketing-v1-and-simple-pipeline.md). Neon/изоляция production сохранены. Этапы A→B заменены сразу development/production targets, без переходного процесса. При конфликте применять актуальные спецификации 02–12.

Дата: 5 октября 2026. Статус: принято владельцем проекта.

## Контекст и варианты

Рассмотрены A — минимальное окружение, B — production и общее тестовое окружение, C — изоляция каждой ветки. У владельца уже есть аккаунт Neon. Принят A для прототипа с обязательным переходом на B до публичного релиза.

## Решение

Провайдер PostgreSQL — Neon в существующем аккаунте владельца; для PkgCompass предусматривается отдельный проект. Аккаунт/квоты ещё не проверены, ресурсы не созданы. Это уточняет [S7](0010-postgres-and-actions.md), сохраняя PostgreSQL + GitHub Actions.

### Этап A: разработка прототипа

- Local и CI используют тестовую PostgreSQL и синтетические CMS/API fixtures; обычные тесты не получают production credentials.
- Neon хранит данные работающего прототипа. Пока публичного production нет, эта БД служит интеграционной средой; после запуска production локальные эксперименты на ней не выполняются.
- Preview использует синтетические данные. Реальный путь CMS/БД проверяется отдельно доверенным интеграционным запуском до перехода на B.
- Разделённые credentials, версионированные миграции, seed, environment-конфигурация и явный target записи вводятся сразу. Один владелец отвечает за контент, доступы, review и восстановление.

### Этап B: до публичного релиза

- Sanity: отдельные datasets `production` и `development`.
- Neon: отдельные production и development ветки с разными подключениями/credentials. Development наполняется тестовым seed; схема создаётся миграциями или schema-only branching.
- Доверенные preview подключаются к development CMS/БД; недоверенные PR остаются на fixtures без секретов реальных сервисов.
- Local/CI сохраняют локальную/временную БД. Live CMS-тесты в development изолируются namespace и выполняются без конкурентной порчи общего seed.
- Production сайт читает опубликованный контент и БД; collector/review/seed/migrations имеют отдельные доступы по своим задачам.

Переход не требует переноса истории в другой провайдер: добавляются тестовые ресурсы и меняются подключения непроизводственных сред. Ветки Neon не заменяют миграции: новую схему применяем к каждой среде явно. Production секреты не выдаются preview; drafts доступны только через авторизованный серверный preview.

Для Next.js на Vercel предлагается pooled connection. Драйвер, способ подключения collector/migrations, регион, тариф и backup выбираются после проверки аккаунта и совместимости. Этот ADR не утверждает платный переход, конкретные квоты и готовое восстановление. Видимость репозитория остаётся открытой: private ранее предлагался, но отдельно не подтверждён владельцем.

## Условия перехода и проверки

Переход на B обязателен перед публичным релизом, проверкой реального публикационного пути и восстановлением в изолированной среде. Проверяем seed → import/retry → publication/preview → cache, применение миграций, отсутствие production-записи из development и согласованное восстановление Sanity/PostgreSQL.

Источники для выбора: [Neon branching workflow](https://neon.com/docs/get-started-with-neon/workflow-primer), [подключение к Neon](https://github.com/neondatabase/website/blob/main/content/docs/get-started/connect-neon.md). Сведения аккаунта ещё не сверены.
