# 0009. Структурированная контентная модель — S6, полный вариант A

> Историческая запись: частично заменена [ADR 0013](0013-marketing-v1-and-simple-pipeline.md). Локализация/редакционная модель сохранены; aiReview добавлен в Studio, операционная модель снимков упрощена по 06/07. При конфликте применять актуальные спецификации 02–12.

Дата: 5 октября 2026. Статус: принято владельцем проекта.

## Контекст и варианты

Рассмотрены A — общая продуктовая сущность и отдельный редакционный документ каждого языка, B — переводы внутри полей, C — английская карточка с миграцией позже. Владелец выбрал весь комплект A и структурированный подход с начала работы.

## Решение

- `library` хранит стабильную идентичность CMS, общий slug и подтверждённые связи с пакетами, репозиториями и категориями.
- `libraryContent`, `categoryContent`, `comparisonContent` и `page` содержат редакционный материал с явной локалью; языковые документы публикуются независимо. В v1 активна только `en`.
- Продукты, категории, пары сравнений, пакеты и репозитории общие для языков; метрики не дублируются в переводах. Немецкий или иной перевод добавляется отдельным контентным документом после готовности.
- Карточки и сравнения используют структурированные поля; Portable Text — для развёрнутых пояснений. Семь редакционных блоков и требования сравнения заданы в [ADR 0006](0006-editorial-criteria.md).
- Главная использует ограниченный набор типов секций, без универсального конструктора произвольных страниц.
- Стабильные ID независимы от slug, названия и npm-имени. Конкретные Sanity `_id` conventions фиксируются при seed.
- Черновики могут быть неполными; публикация требует обязательного контента, валидных references, источников и проверок готовности. Preview защищён, публичная выдача повторно проверяет готовность.
- Редакционные поля и immutable снимки разделены; импорт не меняет редакционные тексты, slug и связи. Конкретное хранилище снимков и scheduler принимаются в S7.

## Последствия и проверка

Больше документов и references, зато переводы не дублируют идентичность/метрики и имеют независимый процесс публикации. Бюджет учитывает локализованные документы и drafts. Стартовая схема реализуется по [модели](../04-content-model.md), уточнённой с учётом семи блоков S3; интерфейс Studio группирует связанные документы для редактора.

Проверяем уникальность entity+locale, references, готовность публикации, сохранение редакционного текста при импорте и отсутствие английского fallback под другой локалью. Доступность публикационных API и точные валидаторы проверяются в прототипе; принятие модели не подтверждает реализацию.
