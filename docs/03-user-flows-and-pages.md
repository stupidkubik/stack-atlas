# PkgCompass: сценарии и страницы ядра

Дата: 5 октября 2026. Статус: актуальные сценарии v1 по [ADR 0013](decisions/0013-marketing-v1-and-simple-pipeline.md); интерфейс ещё не реализован.

Основание: [продуктовая рамка](02-product-and-scope.md), [ADR 0001](decisions/0001-core-and-english-v1.md), [ADR 0002](decisions/0002-pre-code-decisions.md). Приняты CMS-каталог, английский язык v1, AI-readiness, отдельная идентичность продукта и пакета, дедупликация сравнений. Масштаб — 5–8 CMS и 3–5 содержательных сравнений. Форма→CRM и consent/измерение обязательны; личного кабинета нет.

## 1. Карта страниц

Все пользовательские тексты, сообщения ошибок и даты в v1 выводятся на английском. Принят английский префикс `/en/` — [ADR 0008](decisions/0008-public-urls.md); точные redirects, canonical и индексация определены в [SEO-контракте](08-localization-and-seo.md). URL ниже — тот же рабочий контракт, не независимое решение.

| Страница | Принятый URL | Содержимое и основной переход |
| --- | --- | --- |
| Главная | `/en/` | Обещание каталога, вход в CMS-категорию, выбранные CMS и сравнения, ссылка на методологию → категория |
| Категория | `/en/categories/{categorySlug}/` | Описание категории, поиск, фильтры, число результатов, карточки → продукт |
| CMS-продукт | `/en/libraries/{routeSlug}/` | Назначение, применимость, ограничения, источники, метрики, AI-сигналы, альтернативы, доступные сравнения → сравнение / официальный ресурс |
| Сравнение | `/en/compare/{firstSlug}-vs-{secondSlug}/` | Два продукта, общие критерии, различия, оговорки, редакционный вывод → продукт / первоисточник |
| AI-методология | `/en/methodology/ai-readiness/` | Значение индекса, сигналы, область проверки, формула, версии, ограничения, примеры → доказательства |
| Заявка | `/en/request-shortlist/` | Email, сценарий сайта, разрешение на контакт → подтверждённая запись CRM; без подписки |
| Privacy | `/en/privacy/` | Цели, провайдеры/сроки хранения, контакт владельца, изменение analytics consent |
| Ошибка / отсутствие | Исходный запрошенный URL | 404 для неизвестного продукта/пары, понятное сообщение и вход в каталог; технический сбой не маскируется под 404 |

Общие элементы: логотип со ссылкой на главную, навигация в каталог и методологию, breadcrumbs на вложенных страницах, footer с источниками методологии, privacy и Privacy settings; навигация содержит Request a CMS shortlist. Нет переключателя языка до появления опубликованного перевода. Внешние ссылки понятны по подписи; открытие новой вкладки, если используется, обозначено.

В ядре нет отдельной страницы общего поиска: поиск размещён в категории. После добавления категорий общий поиск потребует собственного контракта. Главная предлагает действующую заявку, не обещает рассылку. CTA доступен из comparison, library и nav; entryPoint передаётся только как allowlisted UI enum, не произвольный referrer.

## 2. Найти подходящую CMS

Направление интерфейса принято в [ADR 0011](decisions/0011-interface-direction.md): каталог для разработчика с редакционными элементами, светлая основа и один акцент. Макеты и адаптивность реализуются в выбранном направлении; отдельный продуктовый выбор до кода не нужен.

Путь: главная → CMS-категория → поиск / фильтр → карточка → продукт.

| Шаг | Поведение | Проверяемый результат |
| --- | --- | --- |
| Открыть категорию | Показать опубликованные английские продукты этой категории | Черновики и продукты без готового английского контента отсутствуют |
| Ввести запрос | Регистр не учитывается, пробелы по краям удаляются; поиск по `displayName` и точному `packageName` связанных пакетов | `@example/sdk` находит связанный CMS-продукт; совпадения одного продукта не дублируют карточку |
| Применить фильтр | Рабочие фильтры: `hosting` и `api`; значения заданы в модели | Видны активные фильтры и кнопка очистки; изменение фильтра воспроизводится по URL |
| Сбросить фильтры | Удалить известные параметры, вернуть полный список категории | Результат соответствует входу в категорию без query string |
| Открыть карточку и вернуться | Back возвращает запрос и фильтры | Поиск не теряется при переходе на продукт |

Рабочие query-параметры: `q`, `hosting`, `api`. Для нескольких значений одного фильтра повторяется ключ: `?hosting=cloud&hosting=self_hosted&api=rest`. Значения внутри одного фильтра объединяются OR, разные фильтры — AND. Предлагаемые значения `hosting`: `cloud`, `self_hosted`; `api`: `rest`, `graphql`. Многофункциональный продукт совпадает с каждым поддерживаемым значением. Пустое поле означает «не классифицировано» и не доказывает отсутствие возможности.

Параметры сортируются и дедуплицируются при генерации ссылок. Неизвестные значения игнорируются с безопасным сбросом; некорректное значение не вызывает 500. Запрос ограничен 120 символами; при превышении форма объясняет ограничение. Поиск выполняется после отправки формы или явного применения фильтров: так избегаем лишних записей в истории при каждом символе. Предлагаемый порядок — по `displayName`; сортировка по AI-баллу не нужна для стартового набора.

Карточка содержит название CMS, краткое назначение, редакционные признаки hosting/API и ссылку на продукт. Если выводятся npm-загрузки или AI-балл, рядом есть обозначение объекта измерения, периода и даты. Число загрузок SDK не подписывается «users».

## 3. Изучить продукт и проверить аргументы

Страница отвечает на вопросы в порядке: что решает CMS → когда подходит → когда не подходит → как подключается к JS/TS → ограничения → доступные доказательства → альтернативы.

Обязательные блоки: название и summary; use cases; fit / not fit; limitations; integration notes; официальная документация; источники редакционных утверждений; метрики; AI-readiness; связанные сравнения. Альтернативы — references на опубликованные продукты; отсутствующая альтернатива не создаёт неработающую ссылку.

Метрики содержат подписи пакета/репозитория, периода npm и даты наблюдения. Monorepo-звёзды относятся ко всему репозиторию. При отсутствии релевантного npm-пакета показывается “No comparable npm package selected”; при ошибке — “Could not refresh”, а не ноль. Предыдущее валидное значение можно показать отдельно с его датой и статусом устаревания по [контракту импорта](06-data-pipeline.md).

AI-блок показывает три отдельных сигнала, их состояние, источник, дату и ссылку на методологию. Итог `score` отображается только у полного сопоставимого снимка. Неполный результат показывает “Check incomplete” и причину; предыдущий полный балл, если есть, выводится отдельной записью с датой. Нельзя собирать видимый «новый» балл из разных проверок. Применимость, официальность MCP и формула определены в [AI-методологии](07-ai-readiness.md).

Посетитель может открыть доказательство для каждого положительного сигнала, увидеть подтверждённое отсутствие в области проверки и отличить его от `unknown`/`error`. Community MCP не получает подпись official.

## 4. Сравнить альтернативы

Путь: продукт → выбранное редакционное сравнение → вывод по задаче → официальный ресурс.

В v1 ссылки ведут только на существующие опубликованные сравнения; произвольная пара не генерируется автоматически. Ключ пары строится из отсортированных стабильных ID, URL — из текущих slug в этом порядке. Обратный порядок URL получает 308. `displayOrder` задаёт порядок колонок независимо от идентичности пары. Оба продукта относятся к одной категории.

Страница сравнения содержит:

- контекст задачи и аудиторию, к которым относится вывод;
- таблицу редакционных критериев с ответом для каждой CMS и источниками для проверяемых утверждений;
- условия «выбирайте A, если…» и «выбирайте B, если…», включая ограничения;
- метрики и AI-сигналы с теми же подписями/датами, что на странице продукта;
- дату редакционного пересмотра и ссылки на продукты и документацию.

Разные версии AI-методологии не ранжируются в одной таблице. Неполный балл остаётся пустым с пояснением, а не становится нулём. Отсутствующий показатель не доказывает преимущество другой CMS.

Публикация сравнения требует минимум трёх содержательных критериев и редакционного вывода. Неготовый материал публично возвращает404, доступен в защищённом preview. Готовое сравнение можно явно исключить из индексации через indexingRequested=false:200/noindex, вне sitemap. Сервер повторно проверяет готовность даже после прямой API-публикации.

## 5. Состояния и доступность

| Состояние | Что увидит посетитель | Условие проверки |
| --- | --- | --- |
| Loading | Стабильный каркас страницы, текст загрузки; результат не выглядит как нулевая выдача | Область результата сообщает занятость, фокус не теряется |
| Empty | “No CMS match these filters”, активный запрос и reset | Очистка возвращает список; состояние не выдаётся за ошибку CMS |
| Error страницы | Краткое сообщение и retry / возврат в каталог | Код и состояние отделены от 404; технические детали и секреты не выводятся |
| Error источника | Работают редакционный контент и остальные источники; видна причина отсутствия обновления | Отказ npm не скрывает карточку и не обнуляет GitHub |
| Stale | Последнее валидное значение, его дата и предупреждение | Свежесть считается по наблюдению, а не по времени открытия страницы |
| Not applicable | Причина неприменимости показателя | Нет ложного балла/нуля для CMS без выбранного SDK |
| Not found | 404, вход в каталог | Неизвестные slug не индексируются как полноценные карточки |

На мобильном поиск и фильтры остаются доступными без горизонтального скролла страницы. Таблица сравнения может прокручиваться внутри подписанной области; названия CMS и критериев сохраняют связь с ячейками. Карточки и основной текст идут в одну колонку. Различия не кодируются только цветом.

Клавиатура: skip link, видимый focus, логичный порядок, настоящие ссылки для навигации и кнопки для действий; подписанные поля и связанные ошибки. Изменение числа результатов сообщается ненавязчивой live region после применения. Модальное окно фильтров, если выбрано в дизайне, удерживает фокус, закрывается Escape и возвращает фокус инициатору. Конкретный визуальный дизайн не закреплён этим документом.

## 6. Редакционный путь

Studio → новый черновик / изменение опубликованного материала → проверки → защищённый preview → публикация → обновление публичного кеша → проверка URL.

В preview редактор видит неопубликованный английский контент и признак preview; выход завершает сессию и возвращает опубликованный вариант. Preview не меняет общую выдачу и sitemap. Публикация блокируется обязательными проверками [модели](04-content-model.md); замечания к актуальности метрик не удаляют качественный редакционный материал.

Публикация без деплоя — требование прототипа, а не уже проверенная интеграция. Необходимо проверить конкретные Sanity/Next.js версии, доступ preview, webhook, обновление связанных страниц и резервный TTL. Если обновление кеша временно не выполнено, редактор получает диагностируемое состояние и возможность повторить; исходная публикация не теряется.

## 7. Заявка и согласие

Путь: сравнение/карточка → Request a CMS shortlist → форма → accepted только после CRM success. Validation/rate-limit/retry/unknown result доступны и сохраняют введённое в памяти вкладки. Дубликат не создаёт новую конверсию. Подробный серверный контракт — [09](09-lead-form.md).

Consent имеет unknown/denied/granted; до согласия SDK не загружается, после отказа/отзыва события и необязательное storage отсутствуют. Форма работает во всех состояниях. Privacy settings доступен из footer, не требует аккаунта. SDK/CRM сбой не ломает навигацию. События/воронка — [10](10-measurement.md).

## 8. Приёмка

| Сценарий | Доказательство готовности |
| --- | --- |
| Каталог | Ввод scoped-имени SDK, два фильтра, reload и Back сохраняют результат; черновик не появляется |
| Пустая выдача | Нет совпадений → понятная причина → reset возвращает каталог |
| Продукт | Видны fit/not fit, первоисточники, объект и даты метрик; отказ источника оставляет редакционный контент |
| AI | Полный / неполный / неприменимый пример не путаются; доказательство открывается; старый балл отделён |
| Сравнение | A/B и B/A приводят к одной сущности; мобильная таблица и клавиатура доступны; неполный балл не ранжируется |
| Форма | Валидная заявка в CRM; timeout/повтор/duplicate не выглядят новым успехом; работает без analytics consent |
| Consent | unknown/denied/granted/withdrawal/reload проверены сетью и storage; PII отсутствуют |
| Редактор | Черновик → preview → публикация изменяет публичную страницу без деплоя; неавторизованный preview закрыт |

Стартовый набор/критерии заданы ADR 0005/0006, URL — 08, состояния данных — 06/07. Макеты и live webhook latency проверяются в реализации. Открытых продуктовых блокеров нет; real integration checks остаются задачами прототипа.
