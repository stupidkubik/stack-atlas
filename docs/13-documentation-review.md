# PkgCompass: итоговая сверка документации

Дата: 5 октября 2026. Проверка после пересмотра v1 (ADR 0013) и упрощений учебного v1 (ADR 0014). Это аудит спецификаций, а не верификация работающего приложения.

## 1. Вывод

Документационных блокеров для начала реализации не обнаружено. Обязательный v1: английский каталог из 5–8 CMS и 3–5 сравнений, CMS/preview/публикация, SEO и качество, ограниченный сбор метрик, ручной AI-review, форма → Brevo, consent/PostHog и accepted conversion. Реальная локализация, A/B и подписка остаются расширениями и не заявляются реализованными.

Приоритет: [ADR 0014](decisions/0014-learning-project-simplifications.md), затем [ADR 0013](decisions/0013-marketing-v1-and-simple-pipeline.md) и контракты 02–12. ADR 0001/0002/0004/0008/0009/0010/0012/0013 сохранены с пометками о частичной замене, концепция явно историческая.

## 2. Цельный проход

| Область | Согласованный результат |
| --- | --- |
| Цель → scope → кейс | Учебный портфолио-проект: контентная платформа и измеряемое действие; путь до CRM входит в прототип |
| In/out → приёмка | Локализация, A/B, рассылка, детекторы, история метрик и бэкап заявок не являются release gates |
| Страницы → URL → sitemap | Карточка `/en/tools/{slug}/`; request-shortlist — 200 и index; privacy — 200 и noindex; accepted не отдельный URL |
| Модель → публикация | Сущность `product`; common entity публикуется до locale-content; публичный guard требует готовую пару |
| Сравнения → SEO | Минимум три критерия и вывод; неготовое — 404; готовое с `indexingRequested = false` — 200 и noindex; `disclosure` для пар с Sanity |
| Источники → метрики → UI | Только текущее состояние; last-valid с исходной датой; 0 и null различаются; спарклайн из range API; сверка по идентичности источника |
| AI-review → UI | Читается из Sanity; `mapping_changed` и неполный review дают `score = null`; свежесть 90 дней |
| Pipeline → эксплуатация | Один writer и lock; новый сбор после crash; запуск через Vercel Cron → `workflow_dispatch`, без `schedule` |
| Форма → CRM → события | Email только в Brevo; accepted только после CRM success; идемпотентный upsert и условный переход без lease; один `conversionId` на операцию |
| Origin формы | Production — только `SITE_URL`; development — плюс origin preview-деплоя |
| Consent → атрибуция → воронка | SDK и события только при granted; очистка при отзыве; PII, query и referrer запрещены |
| Targets → права | Development и production изолированы; public reader не читает заявки; preview drafts только на сервере |
| Хранение → restore | Метрики без истории; заявки 30 дней в БД и Brevo; аналитика 90 дней; отчёты 14 дней; backup — только CMS export; restore = export + миграции + новый сбор |
| Оценка → план | 66–106 часов как гипотеза с дизайном (CW-16), пересчёт после прототипа; 44 задачи |

## 3. Автоматические проверки

Проход по 41 Markdown-файлу в `docs/`, README и AGENTS: локальные ссылки и якоря, число колонок таблиц, парность fenced blocks. Отдельным поиском проверено, что в действующих документах не осталось требований к удалённым механизмам: перенос AI-review в БД, история снимков и cleanup, lease и лимит попыток заявок, бэкап заявок, `/en/libraries/`, `schedule` в Actions. Такие упоминания встречаются только в исторических ADR, концепции и в явных списках исключений.

## 4. Что ещё предстоит выполнить

Код и lockfile, настройка аккаунтов, квоты и бюджет, реальные API fixtures и mapping, визуальная система и макеты (CW-16), CRM и аналитический dashboard, preview/webhook smoke, Vercel Cron и dispatch, миграции, restore и удаление, Q01–Q19. У этих задач выбран контракт и способ проверки; новой продуктовой развилки перед стартом они не требуют. Покупка домена не обязательна, Vercel origin достаточен.

Непройденные проверки или недоступный аккаунт могут стать фактическим блокером релиза; аудит markdown их не исключает. Безопасность drafts и PII, честный CRM success и отсутствие событий без consent остаются обязательными gates.
