# PkgCompass: продукт и границы v1

Дата: 5 октября 2026. Статус: актуальная рамка по [ADR 0013](decisions/0013-marketing-v1-and-simple-pipeline.md) с упрощениями [ADR 0014](decisions/0014-learning-project-simplifications.md). Это учебный портфолио-проект: механизмы без видимого потребителя не добавляем. Спецификация до кода; проверенные возможности появятся в README после реализации.

## 1. Цель и пользователь

Портфолио-цель — переход в Frontend / Web Engineer (Marketing & Digital Experience). Проект должен показать управляемый редакционный контент, техническое SEO, доступный интерфейс, производительность, форму → CRM и измерение пользовательского пути с согласием. Локализация и A/B остаются явными незакрытыми пробелами до отдельной итерации.

Посетитель — разработчик, выбирающий CMS для JS/TS-сайта. Обещание: сравнения по задаче, ограничениям и проверяемым источникам; дополнительный контекст — метрики SDK/репозиториев и прозрачные AI-сигналы. Редактор — владелец проекта, публикующий материал без изменения кода.

Трафик, позиции в поиске и рост конверсии не обещаем. Небольшой каталог демонстрирует шаблоны и техническое SEO, без заявления о масштабном programmatic SEO.

## 2. Обязательный первый релиз

| Область | Результат | Граница |
| --- | --- | --- |
| Контент | Одна категория, 5–8 CMS, 3–5 сравнений с собственным выводом | Sanity, Contentful, Strapi, Payload, Directus; Storyblok/DatoCMS добавляются при готовом контенте по ADR 0005 |
| Интерфейс | Главная, каталог, карточки, сравнения, методология, заявка и privacy | Только en; поиск/hosting/API-фильтры в URL; без отдельного поиска и кабинета |
| CMS | Структурированный контент, ограниченные секции, draft, защищённый preview, публикация и webhook | Публичный read layer проверяет готовность; импорт не меняет редакционные поля |
| SEO | Серверный HTML, metadata, canonical, sitemap, redirects, JSON-LD, политика index/noindex | Только содержательные опубликованные страницы; нет hreflang до переводов |
| AI-readiness | Типы основного SDK, llms.txt, официальный MCP, evidence/даты/методология | Ручная проверка в Studio достаточна; балл считается из опубликованного review, только у полного применимого набора; свежесть 90 дней |
| Данные | Seed, dry-run, ежедневные метрики со спарклайном загрузок за 30 дней, отчёт и last-valid fallback | Один writer, повторный сбор после сбоя; хранится только текущее состояние; запуск через Vercel Cron |
| Форма → CRM | Request a CMS shortlist: email, сценарий, разрешение на контакт; запись в Brevo | Помощь бесплатная и некоммерческая, ответ вручную; email только в Brevo; нет подписки, DOI и автоматических писем |
| Измерение | Consent, PostHog EU, типизированные события и воронка до lead_accepted | Только после согласия; без PII, session replay, autocapture и A/B |
| Качество | Доступность, performance, критические тесты, CI, диагностика и восстановление | Приёмка по 11; проверенные команды по 12 |
| Кейс | Публичный сайт, запуск и доказательства CMS/SEO/формы/измерения | Только фактические результаты, ограничения измерения и незакрытые навыки |

Единица каталога — CMS-продукт со стабильным ID. Загрузки SDK не означают число пользователей CMS; звёзды monorepo не суммируются по пакетам. Основной SDK выбирается редактором, его отсутствие допустимо и объясняется.

## 3. Что не входит

Переводы и переключатель языка; A/B и feature flags; подписка, подтверждение адреса, отписка, рассылка; 60–100 продуктов и массовые пары; LLM-аудитор/n8n; Context7/skills/AGENTS.md; публичные JSON/Markdown/llms-full.txt; универсальный builder; история метрик и графики длиннее 30 дней; автоматический discovery всех AI-сигналов; копирование данных между Sanity и БД; бэкапы заявок.

Не создаём пустые модули будущих возможностей. Стабильные ID, document-level локаль, источник и дата наблюдения — достаточная основа расширения.

## 4. Сквозные пути

Посетитель: каталог → CMS → сравнение → первоисточник либо заявка → подтверждённая CRM-запись. Форма работает без согласия на аналитику; в этом случае события и атрибуция не отправляются.

Редактор: seed → draft → preview → публикация → обновление сайта. AI-review публикуется в Studio и сразу виден на сайте после webhook. Робот: опубликованный mapping → запросы → валидация → текущие метрики → отчёт. Сбой оставляет предыдущие валидные данные с прежней датой.

## 5. Порядок реализации

1. Зафиксировать версии/lockfile и создать development targets, схемы, seed и один набор fixtures.
2. Сквозной прототип: 3–5 CMS, одна пара; CMS → страница → preview/webhook; импорт → fallback; форма → CRM; consent → события.
3. По результатам прототипа уточнить команды и оценку, исправить интеграционные ограничения, не увеличивая обязательный scope.
4. Довести интерфейс, редакционный контент, SEO, форму и измерение до полного v1.
5. Проверить критические сценарии, production изоляцию, восстановление, performance и опубликовать кейс.
6. Отдельная итерация: реальный второй язык и затем A/B по действующей воронке. Подписка требует собственного обещания и полного почтового цикла.

Нет зависимости «вся инфраструктура готова → только потом маркетинг»: форма и измерение входят в первый прототип. Визуальная система и макеты ключевых экранов — отдельная задача CW-16 по ADR 0011 и ADR 0014; она идёт параллельно прототипу и предшествует сборке публичного каркаса.

## 6. Успех и границы измерения

| Цель | Доказательство |
| --- | --- |
| Полезность | Сравнение объясняет, какую CMS выбрать для конкретной задачи и почему |
| CMS | Редактор меняет страницу без коммита/деплоя, draft изолирован |
| SEO/качество | HTML/URL/sitemap соответствуют контракту; критический путь доступен; lab performance измерена |
| CRM | Валидная заявка видна в Brevo; повтор не создаёт контакт-дубль; сбой не выглядит успехом |
| Измерение | При согласии прослеживается путь до lead_accepted; при отказе/отзыве сбор прекращается |
| Надёжность | Ошибка источника сохраняет данные; повторный сбор восстанавливает актуальность; экспорт проверен |

Основная конверсия v1 — CRM-принятая заявка, не подтверждённый email и не выполненная консультация. Аналитическая воронка охватывает только согласившихся и не заменяет серверный учёт заявок. Подробные определения и дедупликация — [09](09-lead-form.md) и [10](10-measurement.md).

Продуктовых решений, блокирующих старт, нет. Реальные API, тарифы и аккаунты проверяются задачами прототипа; релиз возможен только после прохождения [приёмки](11-quality-plan.md).
