# Работа в PkgCompass

## Контекст

- Прочитать `docs/00-start-decisions.md`, `docs/14-core-development-plan.md` и профильный план в `docs/plans/` перед реализацией. Нормативный приоритет: ADR 0013 и актуальные спецификации 02–12.
- Текущее состояние и следующий шаг проверять в `docs/work/tasks.md` и последних записях `docs/work/journal/`. Наличие планов не означает готовое приложение.
- Не менять родительский Git-репозиторий. Корень этого репозитория — каталог PkgCompass; проверять `git rev-parse --show-toplevel` перед Git mutations.

## Журнал и артефакты

- Перед работой над задачей создать run: `python3 scripts/worklog.py start <TASK-ID> --summary "Краткая цель"`. Скрипт отмечает задачу `in_progress` и выдаёт локальный run path.
- Записывать значимые изменения, обнаруженные проблемы и результаты проверок через `note` / `check`. После завершения вызвать `finish`: `review`, `blocked`, `planned` или `verified`. Синтаксис — в `docs/work/README.md`.
- `verified` допустим только при выполненном DoD задачи, проверенных артефактах и пройденных обязательных проверках. Скрипт требует `--dod-confirmed`, но не умеет подтвердить DoD самостоятельно. Для критического поведения организовать независимую проверку; субагентов запускать по явной инструкции пользователя, а не автоматически.
- Все screenshots/traces/reports сохранять внутри `artifacts/runs/<run-id>/`. В Git идут только инструкции, task statuses и очищенная сводка журнала. Локальные run files не должны содержать secrets/PII/draft text; `.gitignore` не является защитой данных.
- Не записывать email, IP, request credential, private payload, токены или заголовки авторизации ни в журнал, ни в evidence. CLI текст/command также должен быть очищен до передачи; автоматической редактуры секретов нет.
- Перед commit проверить diff и отсутствие generated/raw artifacts. Результаты реальных, fixture и ручных проверок различать; `not_run` не выдавать за pass.

## Границы

- Этот рабочий журнал — tooling разработки, не collector ledger или runtime логирование приложения. Runtime logs/retention/backup выполняются отдельными задачами DP/LM/QA.
- Не расширять scope v1 и не отмечать FP-01 завершённой по одному Git bootstrap: приложение, версии/lockfile и build ещё предстоят.
- Публикация и расходы выполняются в рамках действующих инструкций владельца. Подготовка локального repo не включает создание remote, внешнюю публикацию или платные upgrades.
